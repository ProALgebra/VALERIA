# Valeria Telegram Bot

Отдельный Telegram-клиент пользовательского интерфейса Valeria. Каждый человек
входит под своей существующей учётной записью Valeria в личном чате с ботом.
Общей учётной записи Valeria в конфигурации нет. Бот работает через существующий
HTTP API сервера; Valeria и её очередь запускаются отдельно.

## Возможности

После входа открывается меню с разделами «Таски», «Консультации», «Диалоги»
и «Профиль». Кнопки проводят пользователя через те же основные действия, что
и веб-интерфейс:

- Выбор доступной таски, ввод дополнительных данных, создание запуска,
  просмотр истории, состояния и результата, отмена активного запуска.
- Создание консультации, просмотр консультаций и истории, продолжение разговора.
- Создание и выбор диалога, чтение истории, отправка сообщений, выбор доступных
  модели и агента, подготовка запроса из шаблона, остановка активного задания.
- Ответы на вопросы агента и запросы разрешений из карточки текущей работы.
- Просмотр профиля и доступных пользовательских настроек, выход из учётной записи.

Для `tasks_only` доступны таски и консультации; свободные диалоги скрыты.
Права на таски, шаблоны, модели, агентов и рабочие папки проверяет API Valeria.
Рабочую папку назначает администратор Valeria. Даже при входе администратора бот
предоставляет пользовательские действия; управление пользователями, общей
очередью и другими административными настройками через него не выполняется.

| Команда | Действие |
| --- | --- |
| `/start` | Начать вход или открыть меню после входа |
| `/login` | Начать вход заново |
| `/menu` | Вернуться к главному меню |
| `/tasks` | Доступные таски и запуски |
| `/consultations` | Консультации |
| `/dialogs` | Диалоги, если они разрешены учётной записи |
| `/profile` | Профиль |
| `/cancel` | Отменить текущий шаг ввода; отмена уже запущенной работы — отдельной кнопкой |
| `/logout` | Завершить сессию Valeria и удалить локальную привязку |
| `/help` | Подсказка по работе с ботом |

Бот опрашивает состояния и новые результаты с интервалом
`TELEGRAM_POLL_INTERVAL_SECONDS` и присылает обновления в личный чат.
После завершения работы опрос диалога приостанавливается, чтобы не удерживать
окружение OpenCode активным. Открытие диалога или новый запрос в боте возобновляют
опрос; повторно доставленные ответы пропускаются.
Посимвольного стриминга нет. Ответы передаются обычным текстом: длинные
сообщения разбиваются с учётом UTF-16, а ответы длиннее 12 000 единиц UTF-16
приходят полностью в UTF-8 `.txt` вместе с кратким просмотром и кнопками.

## Вход и хранение данных

Отправьте `/start` в личном чате, затем логин и пароль Valeria отдельными
сообщениями по запросу бота. Сообщение с паролем бот сразу пытается удалить.
Пароль не сохраняется в SQLite или журнале. Удаление сообщения может не
сработать из-за ошибки Telegram или сети.

Личный чат с ботом — обычный облачный чат Telegram, он не является Secret Chat.
Пароль проходит через Telegram и процесс бота. Используйте такую схему входа
только если она подходит вашей установке; различие облачных и секретных чатов
описано в [Telegram FAQ](https://telegram.org/faq#q-how-are-secret-chats-different).

В SQLite сохраняются cookie сессии Valeria, CSRF-токен, состояние шагов ввода,
наблюдаемые работы и исходящие запросы. Это приватные данные пользователя,
включая тексты запросов. Файл базы создаётся с правами `0600`; каталог и резервные
копии также должны быть закрыты от других пользователей. Пароль Valeria и токен
Telegram в базе не хранятся. По истечении или отзыве сессии Valeria бот просит
войти снова. `/logout` завершает текущую привязку; срок сессии задаёт сервер.

Перед отправкой работы бот сохраняет запрос и стабильный ключ идемпотентности.
При повторе после сетевого сбоя или перезапуска используется тот же ключ, чтобы
сервер Valeria не создавал дубликат задания. Отправки сообщений Telegram могут
повториться при аварии между доставкой сообщения и сохранением её результата.

## Установка и локальный запуск

Нужны Python 3.12+, доступный сервер Valeria и токен, созданный через
[@BotFather](https://t.me/BotFather). Внешний входящий HTTP-порт не нужен:
используется long polling к [Telegram Bot API](https://core.telegram.org/bots/api#getupdates).

Из корня репозитория:

```bash
cd integrations/telegram-valeria-bot
python3 -m venv .venv
.venv/bin/python -m pip install -e .
cp config.env.example config.env
chmod 600 config.env
```

Заполните `VALERIA_BASE_URL` и `TELEGRAM_BOT_TOKEN` в `config.env`. Вместо токена
в конфигурации можно указать `TELEGRAM_BOT_TOKEN_FILE`: путь к файлу, содержащему
только токен и необязательный перевод строки. Непустой путь к файлу имеет приоритет
над `TELEGRAM_BOT_TOKEN`. Этот файл тоже должен быть доступен только владельцу
процесса. Логины и пароли пользователей Valeria в конфигурацию не добавляются.

```bash
.venv/bin/valeria-telegram-bot --env-file config.env
```

Переменные окружения имеют приоритет над значениями `config.env`. Все относительные
пути разрешаются от текущего рабочего каталога. Без `--env-file` CLI ищет
`config.env` в каталоге проекта при установке через `pip install -e`.

| Переменная | Значение |
| --- | --- |
| `TELEGRAM_BOT_TOKEN` | Токен BotFather; обязателен, если не задан файл |
| `TELEGRAM_BOT_TOKEN_FILE` | Необязательный файл с токеном, приоритетнее прямого значения |
| `VALERIA_BASE_URL` | URL Valeria, например `http://127.0.0.1:8081` |
| `TELEGRAM_STATE_DB` | SQLite, по умолчанию `data/telegram-bot.db` |
| `TELEGRAM_ALLOWED_USER_IDS` | Список числовых Telegram user ID через запятую; пустой — без ограничения по ID |
| `REQUEST_TIMEOUT_SECONDS` | Положительный HTTP timeout, по умолчанию `30` |
| `TELEGRAM_LONG_POLL_SECONDS` | Ожидание `getUpdates`, от `1` до `50`, по умолчанию `25` |
| `TELEGRAM_POLL_INTERVAL_SECONDS` | Интервал проверки результатов и повтора после ошибок, по умолчанию `3` |
| `TLS_CA_BUNDLE` | Необязательный читаемый PEM CA bundle для HTTPS Valeria |

Ограничение Telegram ID не заменяет вход в Valeria. Если список пуст, любой
пользователь Telegram может начать вход, но доступ получит только после
авторизации в Valeria. Используйте HTTPS для Valeria при подключении через сеть.
Проверка TLS включена, отключение проверки сертификата не предусмотрено.

## systemd

Каталог `/opt/valeria-telegram-bot` должен содержать файлы этой интеграции и
виртуальное окружение `.venv` с установленным пакетом. Для работы пакета не нужна
установка основного приложения Valeria в это окружение.

1. Создайте системного пользователя и группу `valeria-telegram` без интерактивного
   входа. Установите пакет в `/opt/valeria-telegram-bot/.venv` и дайте этому
   пользователю право чтения проекта и запуска файлов окружения.
2. Скопируйте `config.env.example` в `/etc/valeria-telegram-bot.env`, заполните
   адрес и токен. Установите владельца `root:valeria-telegram` и права `0640`.
   Если используется файл токена, предоставьте сервисному пользователю доступ
   на чтение только этого файла, например с тем же владельцем и правами.
3. В `/etc/valeria-telegram-bot.env` обязательно задайте
   `TELEGRAM_STATE_DB=/var/lib/valeria-telegram/state.db`. Не оставляйте локальный
   путь `data/telegram-bot.db`: значения `EnvironmentFile` имеют приоритет над
   `Environment` в unit-файле.
4. Установите [unit-файл](deploy/valeria-telegram-bot.service) как
   `/etc/systemd/system/valeria-telegram-bot.service`.
5. Выполните команды после настройки конфигурации:

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now valeria-telegram-bot.service
sudo systemctl status valeria-telegram-bot.service
```

`StateDirectory` создаёт приватный каталог `/var/lib/valeria-telegram` для базы
и блокировки процесса. Сервис работает с `UMask=0077`, перезапускается при ошибке
и имеет доступ на запись только к каталогу состояния. При использовании своего
CA-файла разместите его в доступном сервису каталоге, например `/etc`, поскольку
`ProtectHome=true` скрывает домашние каталоги.

На один токен должен работать один long-polling процесс. Файловая блокировка
останавливает второй процесс с той же базой на том же хосте; она не защищает от
запуска того же токена с другой базой или на другой машине. Если у бота настроен
webhook, запуск завершается с понятной ошибкой. Удалите webhook отдельно, если
хотите перейти на polling; приложение само его не меняет.

Токен BotFather, работающий Valeria и запуск сервиса на целевом сервере нужны для
живой проверки. Поставка файлов интеграции сама по себе бота не регистрирует и
не запускает.

## Проверка

Из каталога интеграции:

```bash
.venv/bin/python -m pip install -e '.[dev]'
.venv/bin/python -m pytest -q
.venv/bin/ruff check .
```

Тесты используют подменённые HTTP-транспорты и не отправляют сообщения в Telegram.
Для проверки совместимости с API основного приложения из того же окружения установите
также корневой пакет с тестовыми зависимостями:

```bash
.venv/bin/python -m pip install -e '../..[dev]'
.venv/bin/python -m pytest ../../tests/test_telegram_bot_api.py -q
```
